# Dashboard mounted component checks

This opt-in suite mounts the real `ObservationChart`, `TargetHealthPanel`, `TargetAlertsPanel`, `TargetActivityPanel`, `TargetDeadlockPanel`, `AnalyticsSurfacePanel`, `TargetOnboarding`, `ServersPage`, `OperationsPanel` and `ReportsPanel` under the real `TimeDisplayProvider`, imports the product stylesheet, and serves dedicated HTML/TSX entries through the existing Vite configuration and React plugin. It uses the already installed React, Vite, Playwright and axe dependencies. Harness controls change real props; tests exercise the production transport/parsers with intercepted native synthetic DTOs.

Run from `web` with existing dependencies and the existing Chromium installation:

```powershell
pnpm exec tsc --project tsconfig.component-tests.json --noEmit --pretty false
node --experimental-strip-types --test tests/health-contract.test.mjs tests/alert-contract.test.mjs tests/alert-ui-validation.test.mjs tests/activity-contract.test.mjs tests/deadlock-parser.test.mjs tests/onboarding-contract.test.mjs tests/operations-contract.test.mjs tests/reports-contract.test.mjs tests/analytics-ui-validation.test.mjs
pnpm exec playwright test --config playwright.dashboard-components.config.mjs
```

The suite starts one Vite server at `127.0.0.1:4328` with strict port ownership, then stops it when Playwright finishes. It does not run a product build, write `dist` or require a database. Chart tests reject API traffic; non-chart tests fulfill only registered API requests locally and abort/report unexpected API or external HTTP requests and browser runtime errors before the Vite proxy/backend is reached. The TypeScript configuration inherits source strict flags and checks all product TS/declarations plus TSX harnesses; browser specs and fixtures remain ES modules like the existing Playwright suites.

Seventy-four behavioral tests cover chart evidence/inspection; collector loss/completeness, exact file counters, database paging, inert names, safe failures and late server requests; and permission/state-gated acknowledgement, stable retries with bodyless 204, filtered/missing selections, pending paging and context-change cancellation. Chart, Health, Activity, Deadlock, Analytics, Onboarding, Operations and Reports responsive cases check axe, focus and overflow at 320/1440 pixels. Gap checks use browser-computed stroke bounds/length, without reproducing SVG path strings or model calculations. Pointer cancellation uses a browser event because Playwright's mouse API has no native cancellation command. Component permission flags test rendering/actions, not server authorization.

Thirteen reviewed health/alert/activity/deadlock/onboarding/operations/reports/analytics source-check bundles are replaced with native API/parser and mounted behavior. Health/Activity security constraints and App deadlock/Activity route wiring plus capture-selection copy remain explicitly named lint; the copy assertion is not proof of automatic capture selection. Existing pure model tests remain useful and are retained; this scoped migration does not claim every repository source assertion is behavioral coverage or replace dashboard integration coverage.

Results live in `artifacts/dashboard-components/`: `results.json`, `native-contract-tests.log`, `browser.log`, `results/` for failure traces/screenshots, and `report/` for HTML/axe attachments. Responsive captures use separate stable `screenshots/observation-chart-{320,1440}.png` and `screenshots/health-panel-{320,1440}.png` paths. Activity/deadlock cases also produce `screenshots/activity-panel-{320,1440}.png` and `screenshots/deadlock-panel-{320,1440}.png`. These captures are harness evidence and do not replace product gallery images or historical screenshot counts.

Activity cases cover exact native edge/freshness, wait reset/baseline/loss, history paging, safe retry and target/window cancellation. Deadlock cases cover exact event/detail and Activity URL provenance, inert unknown provider fields, truncation, bounded native response bytes, off-page microsecond identity, paging/retry and cancelled target/selection reads. Matching repository timestamps also exercise independent history component keys and fail on duplicate-key console errors. The responsive cases protect the constrained supporting-evidence grid that keeps wide tables from widening the document.

Onboarding exercises exclusive address bodies, stable retry identity, native HTML validity, pending/unmount guards and loaded-server lifecycle/discovery/search/navigation props. Its axe check is scoped to the registration region; the ServersPage prop tests do not prove fleet loading or server authorization. Operations exercises grouped native legacy/v2 projections, missing/partial states, cancellation, paging/retry, target fencing and AG stream consistency. Reports exercises fixed kinds, UTC windows, bounded generation bodies, inert labels, export hrefs, cancellation and target changes; export backend correctness and retry idempotency are not established. Analytics exercises accessible Retry/Restart paging, truthful inventory scope, safe errors and target/surface/window cursor reset. The response-contract follow-up adds malformed/foreign/oversized registration success refusal with no callback and same-identity recovery, plus unverified report receipt refusal with no exports and safe recovery. Report fixtures use native numeric kinds, finalized state and the backend canonical request digest. Current validation is scoped to affected components and records its own counts; 74 defined cases does not imply every case ran against the latest assets.
