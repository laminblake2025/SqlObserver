# Paired CPU source qualification

The CPU sources are staged library boundaries. They are not registered collectors,
persisted payloads, HTTP/MCP projections or dashboard series. Raw arithmetic can be
numerically comparable while `NativeQualification` remains absent and
`TargetComparisonAdmitted` remains false.

The SQL source brackets sampling on one owned connection under the original
collector deadline. Its pinned query preserves PID, SQL-reported node/instance,
offset-free startup, start/current ticks, exact cumulative user/kernel
milliseconds, SQL-reported processor count and actual physical transport. The
session token is generated by the owner; `ClientConnectionId` is separately
observed from SqlClient. Both must remain stable. SQL-reported processor count
does not replace the native all-group denominator.

The Windows source is local only. It independently observes CIM machine UUID and
boot time, compares the keyed UUID against the current host binding, maps the PID
through native PDH `ID Process`, and preserves native process creation FILETIME,
process-image fingerprint, active logical processors across all groups, individual
raw counter status/type/timebase/anchors and monotonic observations. A shared query
does not prove identical per-counter interval anchors. Failed process evidence
does not erase valid OS evidence.

The configured host binding does not prove that a local PID belongs to the SQL
endpoint. Matching SQL node names and a `sqlservr.exe` basename are insufficient.
The existing integrated connection factory preserves mandatory validated TLS and
explicit TCP routing; no routing, trust, credential or privilege change is made.
Actual shared-memory transport is evidence only, not automatic admission.

Native work must be owned until completion proves it stopped. Cancellation is
advisory; bounded termination and cleanup are separate. An unproven operation
quarantines the target rather than allowing overlapping retries or accepting a
late sample. Unit tests include providers that ignore cancellation.

## Required lab qualification before activation

| Boundary | Required native evidence |
|---|---|
| Target/process association | Independently qualified same-machine SQL endpoint/process mapping under the configured routing and current target/host revisions. |
| Permissions | SQL 2019 `VIEW SERVER STATE`; SQL 2022/2025 `VIEW SERVER PERFORMANCE STATE`; exact Windows counter/process/CIM grants under the monitoring identity, including denied cases. No sysadmin or job-control grants. |
| Interval/formula | Actual raw process and OS types, independent time bases/anchors, idle and controlled load, multicore process values over one CPU, localization and `_Total` aggregation. Unsupported types remain unavailable. |
| Identity | Multiple SQL instances, PDH instance-name reuse, PID exit/reuse, native creation changes, restart, boot change, binding/profile edits and responding-node changes. |
| Topology | More than 64 logical processors, all processor groups, processor-count changes and unavailable topology. |
| Ownership | Cancellation before/during collection, timeout, counter/provider stalls, output cap, helper exit and failed termination with no overlapping new work. |
| Retained dashboard data | Versioned canonical persistence, exact window/epoch gaps, retention boundaries, typed API/MCP contracts, access denial and final browser journeys. None exists for this staged CPU source yet. |

A local helper smoke test can verify native ABI, raw fields and missing-process
behavior. It cannot qualify a remote SQL target, least privilege, SQL/Windows
process association, production admission or historical CPU comparison.
