# Primary availability evidence access ownership

The Health checks availability screen reads two primary v2 projections: replicas and database replicas. Their pagination and publication cutoffs are independent. They share one access owner so an HTTP 401 or 403 from either stream clears both received streams, aborts pending reads, and exposes **Retry AG evidence access**. The mounted Health checks parent retains this latch across tab changes. Polling, ordinary paging, window changes under the same authority, and return-to-latest controls cannot clear it. A changed known authority, server, or target revision starts a new owner. Leaving the workspace or reloading the application creates a fresh owner and performs normal server authorization again; this is not a persistent browser-wide access policy.

The owner binds the selected server, current target revision, supplied access context, and canonical shared window. Equivalent UTC bounds and unrelated database/compare context changes preserve investigated pages. Real window or authority changes retire old requests and remove received facts before the next committed context. Request controllers, owner frames, and epochs prevent late results from crossing unmount, cancellation, or A → B → A navigation. Workspace URL ownership is checked independently of React's rendered scope; a cleared or departed workspace URL cannot remain an owner. Standalone component consumers may start without a workspace hash.

Responses still pass the existing bounded v2 parser and snapshot validator. A received response must also match the selected current revision. The two streams may legitimately return different publication runs or cutoffs; the screen retains its existing mismatch explanation instead of asserting atomic correlation. SQL source `PermissionDenied` coverage is distinct from an HTTP access denial.

Temporary transport, malformed-response, expired-cursor, and cancellation failures preserve actual received facts. Retry repeats that stream's original cutoff and cursor. An explicit successful latest read replaces its investigated page. Cancellation does not create evidence or promote an unverified response.

The primary panel uses scoped dark-theme tokens, wrapping expanded fingerprints, controls/disclosures of at least 44 CSS pixels, and inset keyboard focus with forced-color support. Recovery moves focus within the panel when a focused evidence control disappears; it does not move focus away from an outside workspace control.

This change is frontend access ownership. It adds no collector, database migration, permission, source activation, physical failover classifier, or RPO verdict. Native paired CPU comparison, running/long-running Agent qualification, and physical failover qualification remain separate unfinished requirements. Local synthetic browser validation proves interaction behavior, not native SQL Server admission.
